# Данные и приватность

Документ описывает процесс обработки данных о здоровье: что показывается пользователю, где это
зафиксировано в коде и кто отвечает за процедуры. Приложение хранит чувствительные данные
(пульс, глюкоза, вес, вода, сон, самочувствие), поэтому правовой минимум — часть релиза, а не
«допишем после запуска».

## Что видит пользователь

| Документ | Где в приложении | Версия в коде |
|----------|------------------|---------------|
| Политика конфиденциальности | `/legal/privacy` (ссылка из онбординга и профиля) | `frontend/src/features/legal/content.ts` → `PRIVACY_POLICY_VERSION` |
| Согласие на обработку данных о здоровье | `/legal/consent` (ссылку дают онбординг и профиль) | `frontend/src/features/legal/content.ts` → `HEALTH_DATA_CONSENT_VERSION` |
| Экспорт данных | Профиль → «Экспорт данных» (`GET /api/v1/users/export`) | реализовано |
| Удаление аккаунта | Профиль → «Удалить аккаунт» (`DELETE /api/v1/users/me`) | реализовано |

Версии на бэкенде (`backend/app/core/legal.py`) должны совпадать с фронтендом. При изменении
формулировок поднимите обе версии: приложение запросит согласие заново, а старые записи останутся
в истории профиля.

## Как фиксируется согласие

Онбординг (`POST /api/v1/users/auth/onboarding`) без согласия отклоняется с `400 consent_required`.
При согласии в `users.profile` пишется запись:

```json
{
  "consent": {
    "version": "2026-09-23",
    "accepted_at": "2026-09-23T09:00:00+00:00",
    "source": "onboarding"
  }
}
```

Правила:

- `accepted_at` не перезаписывается при повторном прохождении онбординга — юридически значима
  первая дата;
- версия сохраняется ровно та, которую показали пользователю (клиент присылает
  `consent_version`); если поле не пришло, подставляется текущая версия с сервера;
- факт согласия дублируется в audit-log (`AUTH_ONBOARDING_UPDATE`, поле `consent_version`).

## Процедуры

| Процедура | Как выполняется | Ответственный |
|-----------|-----------------|---------------|
| Запрос субъекта данных (доступ, копия, удаление) | Поддержка принимает обращение, сверяет личность по Telegram-аккаунту, выгружает данные через `GET /api/v1/users/export` или удаляет аккаунт через `DELETE /api/v1/users/me` | владелец продукта |
| Изменение текста политики/согласия | Обновить `frontend/src/features/legal/content.ts` и `backend/app/core/legal.py`, поднять версии, задеплоить | владелец продукта |
| Отзыв согласия | Пользователь удаляет аккаунт; данные удаляются вместе с ним; резервные копии живут ограниченный срок по политике бэкапов | владелец продукта |
| Утечка/инцидент | Ротация секретов, разбор по `docs/security.md`, уведомление затронутых пользователей | владелец продукта |

## Канал для запросов субъектов данных

Поддержка: контакт владельца продукта, указанный в описании бота (`@BotFather` → Description) и в
карточке приложения. Юридический адрес/ИП владельца должен быть добавлен сюда до публичного
запуска — сейчас поле пустое, и это единственное, что осталось заполнить вручную.
